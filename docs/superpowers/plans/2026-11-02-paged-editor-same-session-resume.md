# Same-session owner replacement qualification

> Use disjoint Terra author agents; root owns Git, runtime, builds and checks.

Goal: continue explicit Android editor work after replacing an exited Pi owner
with a real new process using the same saved session ID and file, while an old
editor upload still has a withheld genuine Source acknowledgement.

This is same-session resumption after exit, not two concurrent writers or a
claim that the original editor question remains alive. Phone `sessions.open`
forks a session and is already qualified separately. Use only actual local
Native launch/RPC in-place resume APIs, never inject session maps or grants.
Public paged/outcome gates remain off; positive-outcome incarnation negotiation
is a separate gate. No external release, production host or device change.

## Boundaries

- Hold the last genuine Source chunk ACK after its original handler completed.
- Verify the old owned process identity, terminate only its owned handle and
  observe exit, IPC detach and invalidated original capture.
- Resume the same file/ID through the real local API before releasing the ACK.
  Observe new PID/peer/bridge, Native runtime as applicable, and exact saved-file
  header identity. Reject concurrent-writer substitution or silent session fork.
- Return the original unchanged ACK. The old possible-write request must fail
  without a Source commit/old SDK result. Android retains exact uncertain attempt
  and draft and does not replay. Capture cleanup before the existing expiry bound.
- Through Android UI, explicitly issue a distinct probe and commit a different
  value for a fresh question/grant (Native fresh lease) in that same session.
  Observe the real Source receipt and exactly one matching SDK result from the
  new owner. Preserve old journal entries and observe no replay.
- Preserve source/APK/runner evidence and terminate only fixture-owned resources.
  Native and RPC are separate cases. No physical-Samsung claim.
