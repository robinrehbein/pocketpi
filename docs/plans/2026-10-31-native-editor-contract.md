## Integration amendment after Host preflight
A native source question MUST persistently carry native:true (optional editor-only literal true in Question). This survives journal serialization/replay and prevents a revoked or historical native question from ever becoming ordinary bounded RPC merely because an ephemeral claim map was removed. Base/legacy clients project it to same-ID local_required unless an explicit per-question native-reader predicate permits it. Native positive answers always require active native claim proof; no-claim native editor is never ordinary editor. Android native:true cards require native capability in addition to base editor for Send; Cancel remains possible.
Root owns protocol Question.native validator and projection extension. Existing projectQuestionDetailsEvent/Result gain optional fourth nativeAllowed:(sessionId,question)=>boolean, default denies native:true. Existing detail/base editor booleans and behavior stay unchanged.
Host implementation is split: first a pure identity-keyed lease registry with injected authority/time and bounded state, then root daemon/sessions integration. This replaces the too-broad initial Host task; it does not relax any authority or delivery invariant.
