# Paged editor window viewport

## Evidence and goal

The current paged editor supplies the complete 1 MiB value to one Compose text field. Limiting the field's height fixed an unrepresentable layout constraint, but did not bound its text-layout work. In the private Native production-chain fixture, a measured 45.392-second main-queue delay coincided with a 47.417-second gap between accepted presence messages. The Host closed the matching lease 30.134 seconds after the last accepted presence, consistent with its 15-second TTL and 15-second grace; the original local editor then opened. These observations do not isolate the contribution of every main-thread operation.

Keep the full exact repository draft and existing owner, grant, source proof, upload, cancellation and lease rules. Render and edit only a bounded contiguous window of at most 2,048 UTF-16 code units at a time. Navigation must cover all text, including one very long line, and show the current position. No change extends the Native lease or generates presence independently of the visible chat.

## Editing contract

- Window boundaries never split a UTF-16 surrogate pair. Empty documents and positions at either end are valid. Previous and next actions cover the complete string without deleting, normalizing or implicitly inserting characters; disabled actions indicate an endpoint. First and last controls and a small numeric **jump to section** input make distant positions reachable. Section numbers run from 1 to `max(1, ceil(UTF-16 length / 2048))`; validate and commit input explicitly. A requested section starts at `(section - 1) * 2048`, snapped backward when that offset splits a surrogate pair. Window length remains at most 2,048 code units; a one-unit overlap is acceptable and every character remains reachable.
- The field edits the exact selected range of the full draft. On a change, replace only that range and retain the full result, then call the existing repository edit action with the captured question incarnation. Sending uses the full draft and existing captured grant/source binding, not the window text. Cancellation, loading, quarantine, recovery and stale-question protections retain their existing behavior.
- Selection and IME composition are relative to the visible window. Keep them stable while possible; on navigation or rewindowing, map and clamp the selection to the new window and clear composition only when it cannot be represented there. Flush each visible edit before navigation or submit. All remembered window state, queued edits, navigation and submit callbacks must retain the exact question object by referential identity (`===`), its `EditorQuestionKey`, and the authority generation (`editorScope`); invalidate them on replacement or generation change even if the new JSON and grant bytes are identical. Test actual IME behavior; do not claim it solely from state mapping.
- A large paste is accepted as an exact full-draft replacement of the current range, then the displayed window is reselected and bounded. Never reject or truncate input merely because it exceeds the viewport. Existing full-draft size/control validation governs Send, and the existing retention warning remains authoritative for unretained drafts. Clearly display the selected position after rewindowing.
- Keep the existing full-string repository API for this iteration. Avoid repeated full-draft validation in recomposition where practical. Profile main-thread delay during real operations; a string splice remains O(document size), so large or repeated edits require measured qualification, not an assumed performance guarantee.

## Tasks and gates

1. **Pure window model and tests.** Add `src/main/java/de/joinnoah/pi/remote/EditorWindow.kt` with `internal data class EditorWindow(val start: Int, val end: Int)` and `internal object EditorWindows` exposing `const val MAX_UNITS = 2048`, `fun sectionCount(text: String): Int`, `fun atOffset(text: String, offset: Int): EditorWindow`, `fun atSection(text: String, section: Int): EditorWindow`, `fun previous(text: String, window: EditorWindow): EditorWindow?`, `fun next(text: String, window: EditorWindow): EditorWindow?`, and `fun replace(text: String, window: EditorWindow, replacement: String): String`. Offsets/ranges use UTF-16; reject invalid ranges or section inputs instead of silently changing draft text. `previous` ends at the current start, `next` begins at the current end, both choosing surrogate-safe bounds; `atOffset` snaps a split-pair offset backward and bounds the resulting end without splitting. The last control uses a safe window ending at the document end; expose `fun last(text: String): EditorWindow` for it. Add focused tests in `src/test/java/de/joinnoah/pi/remote/EditorWindowTest.kt` for surrogate pairs at every boundary, empty/short/1 MiB values, section count/jump validation and coverage, one long line, newline-heavy text, combining characters, first/middle/last edits, deletion to empty, large paste and recovery of exact full content. Test oversize and invalid values are retained without silent normalization and remain subject to existing Send validation.
2. **UI integration and instrumentation.** Replace only the paged field with the bounded window, explicit position and navigation controls. Preserve capture and all current disabled/loading/cancel/recovery behavior. Test source-load and normal Send with exact full-draft digest independent of the displayed text; verify first, jumped-to and last windows through navigation. Test replacement with a byte-identical but distinct question object and connection/authority-generation changes, including stale queued edits, navigation and submit. Add real interaction coverage for edits, large paste, selection, IME composition, navigation while editing, stale question/connection, and retained invalid drafts. Measure main-queue delays and actual presence while rendering and editing; do not substitute injected text for a claim of human-scale editing. Update the existing layout fixture so it expects bounded window semantics rather than a full 1 MiB field.
3. **Real chain qualification.** Run fresh task-owned Native and managed RPC fixtures through real source proof, Android viewport and normal UI Send, Host commit, actual owner ACK and original SDK result. Start with unchanged 1 MiB and empty final, then the agreed edited/empty-expand/cancel/lost-ACK matrix. Record exact length/hash, source/owner/grant identity, actual commit receipt, timing and heartbeat gaps. Confirm no local fallback during valid active rendering, and separately test navigation away, background, connection loss and owner replacement still revoke authority. Report physical-device, independent Linux and performance gaps separately; no public capability enablement follows from the private emulator alone.

Before implementation, independently review this plan and the current editor ownership/retention contracts. Root executes builds and device tests; source changes and tests follow only after that review.
